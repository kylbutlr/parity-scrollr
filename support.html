Parity Scrollr

Support and troubleshooting

Some pages cannot be shown inside a comparison. Parity Scrollr does not bypass sign-in, bot protection, or site security controls.

Install or update the extension

Download a browser ZIP from the GitHub releases page, extract it to a permanent folder, and use Load unpacked in your browser's Extensions page with Developer mode enabled. Keep that folder in place. Updates are manual; end comparisons, replace the files in that folder, then select Reload on the extension.

A page stays blank or shows a framing warning

Parity Scrollr automatically retries once with Compatibility mode if a page does not report ready within 15 seconds. The session status shows when this happens. This retry temporarily removes the selected pages' security-policy and framing headers in this comparison tab. It can change which scripts and resources those pages load, and turns off when the comparison ends. If the page still fails, open it directly and confirm that you can access it normally. Pages with their own frame-blocking code, bot challenges, sign-in boundaries, browser-owned pages, and some site policies remain unsupported.

A signed-in page appears signed out

Framed pages can receive different cookie treatment, especially for third-party cookies. Open both sites directly, sign in if appropriate, and try again. Parity Scrollr does not capture, copy, or bypass credentials.

The responsive rendering differs from a device

Viewport controls change CSS width and height only. They do not emulate user agent, device pixel ratio, touch input, orientation APIs, safe-area insets, or hardware. Use real-device or browser device emulation for those checks.

Capture is disabled

Click the Parity Scrollr toolbar icon while the comparison tab is active. This grants temporary capture access for that tab. You can instead enable persistent all-site access in Settings.

Full-page capture fails or looks inconsistent

Keep the comparison tab active until capture finishes. Full-page capture requires document scrolling; pages with an independently scrolling main area should use Capture view instead. Sticky and fixed elements can repeat because the extension captures multiple scroll positions. Lazy content, animation, video, infinite scroll, or a growing page can prevent a stable result. The capture stops after 60 screenshots and scales extremely tall output to browser-safe image dimensions.

Shopify theme previews

Recognized Shopify preview bars are detected automatically and stay hidden through every full-page screenshot, then return after the original scroll positions are restored. This cleanup also runs if capture is cancelled or fails. The storefront body itself is never hidden.

Shopify Admin is not a comparison page

Parity Scrollr blocks Shopify Admin URLs before requesting site access. Open the storefront or theme preview in a regular browser tab, then start the comparison there. The extension does not need access to admin.shopify.com.

Get help

Report an issue on GitHub. Include your browser and extension versions, what you tried, the visible error, whether Compatibility mode was on, and sanitized URLs with private tokens removed. Do not attach confidential captures.
